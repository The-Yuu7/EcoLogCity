# Documento 01: Requisitos Funcionales y Elicitación Holística

## Marco de Elicitación Holística y Ética

El proceso de recolección de necesidades para **EcoLogCity** se desarrolló bajo un enfoque integral, considerando a los diversos actores de la cadena de suministro de DistriRápido S.A.C. y el ecosistema urbano de Huancayo.
- **Perspectiva Glocal:** Se adaptó el diseño a las particularidades geográficas (3,250 msnm) y las condiciones de tráfico específicas del valle del Mantaro, reconociendo que las soluciones de ruteo estándar no abordan el impacto de la altitud en el consumo de combustible.
- **Diversidad de Usuarios:** Se incluyeron entrevistas y talleres de co-creación con choferes, administradores logísticos y analistas ambientales, para garantizar que la interfaz y los procesos sean accesibles y eficientes.
- **Perspectiva Ética:** La optimización no solo persigue rentabilidad, sino que tiene el mandato de reducir la huella de carbono ($CO_2$) y minimizar el impacto ambiental y acústico en zonas residenciales de la ciudad. Se garantiza la privacidad de las ubicaciones de los clientes mediante políticas de retención y anonimización de datos.

## Especificación Atómica de Requisitos Funcionales

### RF-001: Geocodificación de Pedidos

- **Descripción Atómica:** El sistema debe transformar direcciones textuales ingresadas en coordenadas geoespaciales (latitud y longitud) utilizando la API de OpenStreetMap cuando un nuevo pedido es registrado.

- **Prioridad:** Alta

- **Criterios de Aceptación (Gherkin / BDD):**

#### Ruta Gold (Camino Ideal Principal)
DADO un operador logístico autenticado con permisos de registro
CUANDO el usuario ingresa una dirección textual válida en Huancayo Cercado
ENTONCES el sistema procesa la solicitud, obtiene las coordenadas exactas y confirma la transacción guardando el pedido con su geolocalización.

#### Ruta Feliz (Flujos Alternativos Válidos)
DADO un operador logístico que ingresa una dirección con formato incompleto
CUANDO el usuario selecciona una ubicación aproximada en el mapa interactivo (Visor Cartográfico)
ENTONCES el sistema toma las coordenadas del pin seleccionado en el mapa y completa el registro satisfaciendo el objetivo.

#### Ruta Infeliz (Casos Borde y Manejo de Errores)
DADO un operador logístico intentando registrar un pedido
CUANDO el usuario ingresa una dirección fuera de la zona de cobertura (ej. otra región o país)
ENTONCES el sistema deniega la acción, mantiene el estado consistente y despliega el mensaje de error explícito "Dirección fuera del área de servicio de Huancayo".

### RF-002: Optimización de Rutas (VRPTW & Green VRP)

- **Descripción Atómica:** El sistema debe generar una secuencia de ruta óptima que minimice la distancia y las emisiones estimadas de CO₂ cuando el administrador solicita la planificación diaria de la flota.

- **Prioridad:** Alta

- **Criterios de Aceptación (Gherkin / BDD):**

#### Ruta Gold (Camino Ideal Principal)
DADO un administrador logístico autenticado en el módulo de enrutamiento
CUANDO el usuario selecciona los pedidos del día y ejecuta el motor metaheurístico
ENTONCES el sistema procesa los datos, asigna las paradas a los vehículos disponibles respetando las ventanas horarias y muestra las rutas óptimas.

#### Ruta Feliz (Flujos Alternativos Válidos)
DADO un administrador que requiere forzar la asignación de un pedido a un conductor específico
CUANDO el usuario opta por fijar el pedido manualmente antes de ejecutar el motor
ENTONCES el sistema completa la operación optimizando el resto de la ruta alrededor de esa restricción impuesta.

#### Ruta Infeliz (Casos Borde y Manejo de Errores)
DADO un administrador ejecutando la optimización con una flota insuficiente
CUANDO la capacidad total de los vehículos activos es menor al volumen de carga de los pedidos
ENTONCES el sistema deniega la acción automática, mantiene el estado consistente y despliega un mensaje de error alertando sobre la "Falta de capacidad vehicular para cubrir la demanda".

### RF-003: Re-enrutamiento Dinámico

- **Descripción Atómica:** El sistema debe recalcular y actualizar la secuencia de entregas restante cuando se reporta un nuevo evento de tráfico crítico o una cancelación durante la operación.

- **Prioridad:** Media

- **Criterios de Aceptación (Gherkin / BDD):**

#### Ruta Gold (Camino Ideal Principal)
DADO un chofer en ruta con la aplicación móvil/web activa
CUANDO el sistema detecta un evento de congestión severa mediante integraciones de tráfico
ENTONCES el sistema procesa la nueva información, recalcula la ruta óptima para las paradas pendientes y notifica al chofer con la nueva secuencia.

#### Ruta Feliz (Flujos Alternativos Válidos)
DADO un chofer que informa de un cierre de calle inesperado manualmente
CUANDO el usuario marca un tramo como bloqueado en su interfaz
ENTONCES el sistema recalcula la ruta omitiendo el tramo afectado y actualizando el ETA (Tiempo Estimado de Llegada).

#### Ruta Infeliz (Casos Borde y Manejo de Errores)
DADO un fallo en el motor de mapas o conexión a internet
CUANDO el sistema intenta recalcular la ruta tras una desviación
ENTONCES el sistema suspende el re-enrutamiento, mantiene la ruta original en caché (estado consistente) y despliega un mensaje de "Modo Offline - Siga la ruta original".
