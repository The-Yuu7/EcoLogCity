# Documento 05: Evaluación e Identificación del Stack Tecnológico

## Criterios de Evaluación Multidimensional

Para el desarrollo del PMV de EcoLogCity, se evaluaron tres alternativas tecnológicas que permitan soportar la concurrencia de la API, el cálculo intensivo de la metaheurística y un diseño sustentable (bajo consumo energético).

| Criterio de Evaluación | Alternativa 1: MERN (Node/Express + React + MongoDB) | Alternativa 2: MERN Híbrido (Node/Express + React + PostgreSQL) | Alternativa 3: Python / FastAPI + React + PostgreSQL |
| :--- | :--- | :--- | :--- |
| **Curva de Aprendizaje** | Baja (JavaScript unificado en todo el stack) | Baja-Media (JavaScript unificado + SQL relacional) | Media (Python en backend, JS en frontend, SQL) |
| **Costo de Infraestructura** | Moderado (Node asíncrono, pero alto costo en BD documental a escala) | Moderado (Node asíncrono + eficiencia de DB relacional) | Bajo (FastAPI asíncrono, bajo consumo RAM y CPU) |
| **Soporte Comunitario** | Masivo / Muy Alto | Masivo / Muy Alto | Alto / Crecimiento acelerado |
| **Eficiencia Energética / Eco-Design** | Media | Media-Alta | Alta (Métricas de cómputo eficientes, menor latencia) |
| **Adecuación al Dominio (Algoritmos)** | Baja (Node no es óptimo para carga CPU de VRP) | Baja (Node no es óptimo para algoritmos de cálculo intensivo) | Muy Alta (Ecosistema científico y matemático nativo de Python) |

## Justificación Técnica Formal

El equipo ha seleccionado una variante muy cercana a la **Alternativa 3** (en base a la arquitectura final propuesta en el sistema, adaptada a un backend `Node` y/o `FastAPI`), decantándose por un modelo de **Servicios REST Backend con conexión a PostgreSQL (con extensión PostGIS)** y un **Frontend en React.js**. 

**Justificación:**
1. **Modelado Geográfico Riguroso:** El problema VRPTW demanda cálculos espaciales. PostgreSQL, junto con su extensión PostGIS, ofrece las herramientas nativas más robustas del mercado open-source para consultas geoespaciales eficientes.
2. **Escalabilidad y Rendimiento Asíncrono:** Para el manejo de las concurrencias y solicitudes al servidor, el uso de Node.js / FastAPI garantiza un procesamiento de peticiones asíncronas no bloqueantes. Para la resolución matemática intensiva del algoritmo VRP, se delegará el procesamiento a módulos especializados (o microservicios) donde tecnologías como Python (o C++) destacan por su ecosistema matemático, reduciendo los tiempos de respuesta y, en consecuencia, el tiempo de encendido del servidor, apoyando los objetivos de **Eco-Design** y reduciendo la huella de carbono de la propia plataforma.
3. **Eficiencia en la Interfaz (UX):** React.js permite la construcción ágil de la Single Page Application (SPA), garantizando un renderizado rápido e interactivo del mapa Leaflet en los dispositivos móviles de los conductores.
