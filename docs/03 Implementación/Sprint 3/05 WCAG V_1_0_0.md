### Hallazgos en el Principio Perceptible

#### HAL-001 — Iconos Emoji sin Alternativa Textual (1.1.1)

| Campo | Detalle |
|---|---|
| **ID** | HAL-001 |
| **Criterio** | 1.1.1 — Non-text Content (Nivel A) |
| **Página** | `login.html` |
| **Elemento** | Divs decorativos con emojis: `🏠`, `🚀` |
| **Estado** | ✅ **CORREGIDO en Sprint 3** |

**Descripción del Problema:**  
Los divs que contienen emojis usados como iconos decorativos no tenían atributos de accesibilidad. Los lectores de pantalla (NVDA, VoiceOver) leían el nombre de los emojis en el idioma del sistema operativo ("house", "rocket"), interrumpiendo la navegación con contenido irrelevante.

**Código Antes de la Corrección:**
```html
<div class="icon-decoration">🏠</div>
<div class="icon-decoration">🚀</div>
```

**Código Después de la Corrección (aplicada en Sprint 3):**
```html
<div class="icon-decoration" aria-hidden="true">🏠</div>
<span class="sr-only">Plataforma de logística EcoLogCity</span>

<div class="icon-decoration" aria-hidden="true">🚀</div>
<span class="sr-only">Optimizador de rutas</span>
```

**CSS agregado:**
```css
.sr-only {
  position: absolute;
  width: 1px;
  height: 1px;
  padding: 0;
  margin: -1px;
  overflow: hidden;
  clip: rect(0, 0, 0, 0);
  white-space: nowrap;
  border: 0;
}
```

**Resultado:** Los emojis son ignorados por lectores de pantalla (`aria-hidden="true"`). El contexto descriptivo está disponible para tecnologías asistivas mediante el span `.sr-only` visualmente oculto pero presente en el árbol de accesibilidad.

#### HAL-002 — Ratio de Contraste Insuficiente en Placeholder (1.4.3)

| Campo | Detalle |
|---|---|
| **ID** | HAL-002 |
| **Criterio** | 1.4.3 — Contrast (Minimum) (Nivel AA) |
| **Página** | `login.html` |
| **Elemento** | Texto placeholder de los campos de formulario (`::placeholder`) |
| **Estado** | ✅ **CORREGIDO en Sprint 3** |

**Descripción del Problema:**  
El color original del texto placeholder era `#94a3b8` sobre fondo blanco `#ffffff`, resultando en una ratio de contraste de **2.8:1**. WCAG 2.1 criterio 1.4.3 exige un mínimo de **4.5:1** para texto de tamaño normal (o 3:1 para texto grande ≥18pt).

**Medición de Contraste (herramienta: Colour Contrast Analyser):**

| Estado | Color Texto | Color Fondo | Ratio | WCAG AA |
|---|---|---|---|---|
| **Antes** | `#94a3b8` | `#ffffff` | 2.8:1 | ❌ Falla |
| **Después** | `#64748b` | `#ffffff` | 4.6:1 | ✅ Aprueba |

**Corrección Aplicada (Sprint 3):**
```css
/* Antes */
input::placeholder {
  color: #94a3b8;
}

/* Después */
input::placeholder {
  color: #64748b; /* ratio 4.6:1 sobre fondo blanco — cumple AA */
}
```

**Resultado:** El nuevo color `#64748b` (Slate-600 en la escala de Tailwind) mantiene la apariencia visual de "placeholder" sin sacrificar legibilidad para usuarios con baja visión o en condiciones de iluminación adversa.

### Hallazgos en el Principio Operable

#### HAL-003 — Mapa Interactivo No Alcanzable por Teclado (2.1.1)

| Campo | Detalle |
|---|---|
| **ID** | HAL-003 |
| **Criterio** | 2.1.1 — Keyboard (Nivel A) |
| **Página** | `index.html` |
| **Elemento** | `<div id="map">` (contenedor del mapa Leaflet) |
| **Estado** | ✅ **CORREGIDO en Sprint 3** |

**Descripción del Problema:**  
El contenedor del mapa de rutas (`<div id="map">`) no era alcanzable mediante la tecla Tab, por lo que usuarios que navegan exclusivamente con teclado no podían interactuar con el mapa ni recibir información sobre su contenido.

**Código Antes de la Corrección:**
```html
<div id="map" style="height: 400px;"></div>
```

**Código Después de la Corrección (aplicada en Sprint 3):**
```html
<div id="map"
     style="height: 400px;"
     tabindex="0"
     role="application"
     aria-label="Mapa de rutas de entrega de DistriRápido S.A.C. en Huancayo. Use las teclas de flecha para navegar una vez enfocado."
     aria-describedby="map-instructions">
</div>
<p id="map-instructions" class="sr-only">
  Mapa interactivo que muestra las rutas optimizadas de entrega.
  Presione Enter para activar la interacción con el mapa.
  Use las flechas del teclado para desplazarse y +/- para hacer zoom.
</p>
```

**Resultado:** El mapa es ahora alcanzable por teclado (Tab order), tiene un label descriptivo que los lectores de pantalla anuncian al recibir el foco, y las instrucciones de navegación están disponibles mediante `aria-describedby`.

### Hallazgos en el Principio Robusto

#### HAL-004 — Ausencia de Landmark `role=main` y Estructura ARIA (4.1.2)

| Campo | Detalle |
|---|---|
| **ID** | HAL-004 |
| **Criterio** | 4.1.2 — Name, Role, Value (Nivel A) |
| **Páginas** | `login.html`, `index.html` |
| **Elemento** | Ausencia de landmarks semánticos (`<main>`, `<nav>`, `<header>`, `<footer>`) |
| **Estado** | 🔴 **PENDIENTE — Planificado para Sprint 4** |

**Descripción del Problema:**  
Las páginas no utilizan elementos HTML5 de landmark semántico ni atributos `role` de ARIA para estructurar el contenido en regiones navegables. Los usuarios de lectores de pantalla (especialmente usuarios avanzados) utilizan atajos de teclado (H para encabezados, M para main, etc.) para navegar eficientemente por la página sin recorrer todo el contenido secuencialmente.

**HTML Actual:**
```html
<!-- login.html — estructura actual sin landmarks -->
<body>
  <div class="login-container">
    <div class="login-header">...</div>
    <form id="loginForm">...</form>
  </div>
</body>
```

**HTML Propuesto para Sprint 4:**
```html
<!-- login.html — estructura con landmarks semánticos -->
<body>
  <header role="banner">
    <h1>EcoLogCity</h1>
    <p>Optimizador de Rutas para DistriRápido S.A.C.</p>
  </header>
  <main role="main" id="contenido-principal">
    <h2>Iniciar Sesión</h2>
    <form id="loginForm" aria-label="Formulario de inicio de sesión">
      ...
    </form>
  </main>
  <footer role="contentinfo">
    <p>© 2026 EcoLogCity — DistriRápido S.A.C.</p>
  </footer>
</body>
```

**Impacto de la Corrección:**
- Usuarios de NVDA/VoiceOver pueden usar `F6`/`D` (landmark navigation) para ir directamente al formulario.
- El árbol de accesibilidad muestra una estructura lógica de `banner → main → contentinfo`.
- Mejora el SEO como beneficio adicional.

**Responsable:** Quispe Aquino Junior | **Fecha Límite:** 11/11/2026

#### HAL-005 — Botón de Login sin `role=button` Explícito (4.1.2) — ACEPTADO

| Campo | Detalle |
|---|---|
| **ID** | HAL-005 |
| **Criterio** | 4.1.2 — Name, Role, Value (Nivel A) |
| **Página** | `login.html` |
| **Elemento** | `<button type="submit">Ingresar al sistema</button>` |
| **Estado** | ✅ **ACEPTADO — No requiere cambio** |

**Descripción:**  
El elemento `<button type="submit">` no tiene el atributo `role="button"` explícito. Sin embargo, el elemento `<button>` en HTML tiene rol implícito de `button` según la especificación HTML-AAM (Accessibility API Mappings). Los lectores de pantalla anuncian correctamente "Ingresar al sistema, botón".

**Decisión:** Agregar `role="button"` a un elemento `<button>` sería redundante y potencialmente confuso. El ARIA Authoring Practices Guide (APG) indica explícitamente que no se deben agregar roles redundantes a elementos nativos de HTML. **Hallazgo marcado como aceptado.**
